# 生产部署文档（GPU 服务器）

目标环境：Linux + NVIDIA GPU（当前 4090D，22 核）**裸机部署**，不用 Docker。
**适用范围：仅 01-OCR流水线（P1）与 02-制度知识库（P2）两个项目。**
03-任务管理系统不在本文档范围内：它不依赖 GPU、也不调用 P1/P2 服务，
随仓库自带 docker-compose.yml，在本地 `docker compose up` 部署即可，
与本文档及 GPU 服务器无关。
本目录 6 个脚本即全部运维入口；新人按本文档从零到验证一条线走完。

| 脚本 | 作用 |
|---|---|
| start.sh | 起 1 个 API(8700) + N 个 OCR worker（默认 gpu-1..4），生产配置全在此 |
| stop.sh | 按 PID 安全停 API + 全部 worker（绝不 pkill -f） |
| restart_api.sh | 只重启 API（改了 API 层代码后用，worker 不动） |
| start_p2.sh | 起项目二知识库 API（127.0.0.1:8800，限 4 线程，仅本机/隧道可达） |
| monitor.sh | 采样 GPU 利用率/显存 + cgroup CPU 用量：`bash monitor.sh 秒数 输出文件` |
| fetch_nvidia.sh | 预下载 GPU 版 paddle 的 15 个 nvidia cu12 依赖 wheel（阿里源、PK 魔数校验、断点续传，产物在 /tmp/nvdl） |

## 一、目录约定（服务器）

仓库根目录 = `/root/rivermind-data`（start.sh 内已写死，换机器需同步改脚本路径）。
日志统一写 `/root/rivermind-data/logs/`，脚本自身不建日志目录，首次部署先：

```bash
mkdir -p /root/rivermind-data/logs /root/rivermind-data/tmp
```

## 二、前置条件

1. **NVIDIA 驱动**已装：`nvidia-smi` 正常输出（CUDA 12.6 系列）；
2. **Python 3.11**（开发验证版本 3.11.9）；
3. **LibreOffice + 中文字体**（Office 转 PDF 依赖，缺中文字体转换产物是豆腐块、
   OCR 结果不可用）：`apt install libreoffice-writer libreoffice-calc libreoffice-impress fonts-noto-cjk`。

## 三、安装依赖

```bash
cd /root/rivermind-data/01-OCR流水线/服务
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

requirements 钉的是 **CPU 版** `paddlepaddle==3.2.2`，GPU 服务器必须替换为 GPU 版：

```bash
# nvidia 依赖 wheel 很大、直装易超时：先预下载 15 个（串行、可重跑续传）
bash /root/rivermind-data/deploy/fetch_nvidia.sh
.venv/bin/pip uninstall -y paddlepaddle
.venv/bin/pip install /tmp/nvdl/*.whl          # 先装 nvidia 依赖
.venv/bin/pip install paddlepaddle-gpu==3.2.2  # 依赖已满足，不会重下；若源中
                                               # 无此版本，按 Paddle 官网 CUDA12.6
                                               # 指引选同系列版本
# 验证 GPU 可用（应报告成功/GPU）
.venv/bin/python -c "import paddle; paddle.utils.run_check()"
```

版本钉死理由：Paddle 3.3.1 启用 oneDNN 会报 PIR 属性转换错误，故固定 3.2.2；
`auto` 后端只对已验证的 3.2.2 开 CPU 加速，其他版本自动退回普通 Paddle 并告警。
CPU/GPU 的结果缓存按运行时签名自动分离，切换设备无需清缓存。

## 四、启动

```bash
cd /root/rivermind-data
bash deploy/start.sh                        # API(0.0.0.0:8700) + 4 worker(gpu-1..4)
WORKERS='gpu-1 gpu-2' bash deploy/start.sh  # 只起 2 个 worker
bash deploy/restart_api.sh                  # 只重启 API（worker 不动）
bash deploy/stop.sh                         # 全停
bash deploy/start_p2.sh                     # 项目二(127.0.0.1:8800)
```

start.sh 固化的生产配置（与代码默认值的差异全部在此，改配置=改脚本后重启）：

| 环境变量 | 生产值 | 代码默认 | 含义 |
|---|---|---|---|
| OCR_DEVICE | gpu:0 | cpu | GPU 推理 |
| OCR_STRUCTURE_EAGER | 1 | 0 | worker 启动即预加载 PP-StructureV3 |
| OCR_MAX_RUNNING_DOCUMENTS | 3 | 1 | 扫描文档全局并发 |
| OCR_CARD_RETRY_SIDE | 1280 | 0（关） | 证件低置信时按 1280 检测长边重试 |
| OCR_API_HOST | 0.0.0.0 | 127.0.0.1 | 对外提供 API |
| OCR_CARD/DOCUMENT_CPU_THREADS | 4 | 4 | 引擎 CPU 线程 |
| TMPDIR | /root/rivermind-data/tmp | /tmp | 与 uploads 同盘，避免 Office 转换跨盘改名 EXDEV |
| OCR_TRIAL_DIRS | 公开样例/自造测试集/OCR测试集50张 | 自造测试集 | 证件配置试跑的评测集来源（目录需含 标准答案.json + 图片） |

## 五、验证

```bash
# 1) 离线测试（不依赖服务，装完依赖即可跑）
cd /root/rivermind-data/01-OCR流水线/服务
.venv/bin/python tests/test_d0_offline.py
.venv/bin/python tests/test_card_assembly.py
.venv/bin/python tests/test_routing_and_roles.py
.venv/bin/python tests/test_task_service.py
.venv/bin/python tests/test_unified_pipeline.py
.venv/bin/python tests/test_batches_eval.py

# 2) 服务健康（start.sh 后；status=ok 且 worker 全 alive、两模型 loaded）
curl -s http://127.0.0.1:8700/api/v1/health
```

首次识别会自动下载公开模型到 `~/.paddlex`（之后复用）。证件与文档均在
服务器本地处理，不上传任何外部模型服务。

## 六、常见问题

| 现象 | 原因与处理 |
|---|---|
| Office 转 PDF 乱码/豆腐块 | 缺中文字体 → 装 fonts-noto-cjk |
| GPU 不生效（日志仍按 cpu 跑） | 装的是 CPU 版 paddle → 按第三节替换并 run_check 验证 |
| Office 转换报 EXDEV | TMPDIR 与 uploads 跨文件系统 → 保持 start.sh 的 TMPDIR 设置 |
| nohup 启动即退/无日志 | logs 目录不存在 → mkdir -p /root/rivermind-data/logs |
| 证件配置试跑找不到测试集 | OCR_TRIAL_DIRS 指向的目录需含 标准答案.json + 图片 |
