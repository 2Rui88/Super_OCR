# 项目方案：OCR 流水线（证件识别 + 扫描文档识别）

提交人：　　　　提交日期：

> 一句话：本地 PaddleOCR 双入口（证件用裸识别、扫描页用整页结构化），PyMuPDF 直读文字层，规则校验器兜底，全部结果带位置和置信度，YAML 配置化证件类型。

## 1. 我对需求的理解

做 一个"图片变数据"的流水线服务，两条业务线：

1. **证件线（快、同步）**：身份证正/反面、营业执照、驾驶证 4 类，自动判断类型，抽字段带置信度，规则校验（校验位、日期一致性等），问题字段标红并写明原因。
2. **文档线（慢、异步）**：多页 PDF 逐页识别。**有文字层的页直接读文字（免 OCR），扫描页才做 OCR**，每页标注用了哪种方式；表格按行列还原不能揉散；每个文字块和表格都要带页面位置。
3. **通用底座**：批量排队+进度+单重试失败项；内容哈希防重复；导出 Excel/JSON（证件号防科学计数法）；一键评测准确率；接口文档齐全。
4. **接口是给项目二用的**：扫描件识别走本服务接口，契约第一天定死且稳定。
5. **测试集本身是评分项**：每类 ≥10 张虚构证件，覆盖翻拍/倾斜/模糊/反光/错号，附标准答案和生成脚本。

## 2. 需要确认的问题

| # | 问题 | 我的建议 |
|---|---|---|
| 1 | 验收机器是否有 GPU / 是否允许租 GPU | 先按纯 CPU 本地方案做（成本 0）；若单页耗时超预期再租卡，费用约 100~300 元 |
| 2 | 驾驶证字段范围 | 以 `标准答案.json` 出现的字段为准，配置文件里可增删 |
| 3 | 文档识别准确率怎么衡量 | 我自行设计：字级准确率（编辑距离）+ 表格单元格匹配率 + 页面方式判定正确率（见 §7） |
| 4 | 现场加新证件的演示形式 | 递增一个 YAML 文件（含分类关键词、字段锚点、校验规则），重启即生效，不改代码 |
| 5 | 扫描件质量差的兜底 | 质量哨兵标"OCR 质量可疑"并说明原因，不硬输出烂结果 |

## 3. 总体设计

### 3.1 系统结构

```
上传 → sha256 内容哈希缓存 ─ 命中 → 直接返回历史结果
          │未命中
          ▼
      文件路由（图片→证件线 / PDF→文档线）
          │
   ┌──────┴───────────────────┐
   证件线（同步，秒级）          文档线（异步：任务号+轮询）
   │ ① PP-OCR: det+rec+cls     │ PDF 逐页判定（唯一的 if）：
   │   → 行级[bbox+文字+置信度] │   文字层≥20字 且 图片覆盖<50%？
   │ ② 类型分类：YAML 关键词评分 │    ├─ 电子页: get_text + find_tables
   │ ③ 字段组装：YAML 锚点+正则 │    │   + 嵌入大图单独抠出跑结构化 → 标 text_layer
   │   置信度=覆盖行的 min      │    └─ 扫描页: 取内嵌图(不重采样) → PP-StructureV3
   │ ④ 规则校验器 → 标问题+原因 │        → 整页 blocks → 标 ocr
   └──────┬───────────────────┘ │ 质量哨兵 → 表格HTML+行影子文本
          ▼                     └──────┬──────────────┘
        统一契约（blocks/fields，全带 bbox）
          │
   任务状态机 → 批量/单重试 → 导出 Excel/JSON → 评测报表
```

### 3.2 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 语言/框架 | Python 3.11 + FastAPI + SQLite | 生态与 OCR 无缝；异步接口原生；单机演示 SQLite 足够 |
| PDF 解析 | PyMuPDF | 文字层/表格/渲染/图片检测一个库全包 |
| OCR 引擎 | **PaddleOCR 3.x**（详见 3.3） | 开源本地、行级置信度和坐标是真实值、表格还原能力内置 |
| 不选云 API | — | 免费额度不稳、验收现场网络是单点、证件类内容不宜外传 |
| 不选 VLM | — | 会幻觉编造号码（证件场景致命）、置信度是编的、坐标粗糙；规则校验器才是兜底 |

### 3.3 模型选型（核心）：一个包、两个入口

| 入口 | 用在哪条链路 | 作用 |
|---|---|---|
| **PP-OCRv5 det+rec+cls**（server 模型） | **证件线** | 行级识别：每行 [bbox + 文字 + 真实置信度]。不用 PP-Structure 跑证件——版面重排会干扰锚点组装，裸行序列正是字段组装想要的 |
| **PP-StructureV3 整页**（server 模型） | **文档线·扫描页** | 整页一次调用：markdown（段落/表格 HTML/版面标签/流程图文字），表格保持 HTML 不散架 |
| 预处理三开关 | 两条线 | `use_doc_orientation_classify`（整页 0/90/180/270）+ `use_textline_orientation`（行方向）+ `use_doc_unwarping`（弯曲/翻拍矫正）→ 覆盖"歪了摆正"必做项 |
| PyMuPDF（不是模型） | **文档线·全部页** | 文字层直读、find_tables、页面渲染、嵌入图检测 |

**耗时预估**（验收时给出实测值）：

| 场景 | CPU（i5 级） | GPU（如租 4090） |
|---|---|---|
| 单张证件 | 1~3 秒 | <0.5 秒 |
| 扫描页（含表格） | 5~10 秒/页 | 0.5~2 秒/页 |
| 电子页（直读文字层） | <0.1 秒/页 | 同左 |

### 3.4 统一数据契约（第一天定死）

核心思想（借鉴 leaudit 生产架构）：**切块契约与来源无关**——电子页和扫描页殊途同归，下游永远只面对一种 blocks 结构。

```jsonc
// 文档结果
{ "file_sha256": "...", "pages": [{
    "page_num": 3, "source_mode": "ocr",        // text_layer | ocr —— 必做项"注明方式"
    "duration_ms": 6200,
    "blocks": [
      {"type": "text",  "text": "...", "bbox": [x1,y1,x2,y2]},
      {"type": "table", "html": "<table>...</table>",
       "row_texts": ["职级: 处级 | 住宿: 500元/天", "...],   // 带表头的行影子文本
       "bbox": [...]},
      {"type": "figure", "caption": "图1 报销流程",
       "linear_text": "提交申请 → 部门审核 → ...", "bbox": [...]}
    ]}],
  "markdown": "..." }                             // 加分项

// 证件结果
{ "doc_type": "id_front", "type_confidence": 0.92,
  "fields": [
    {"name": "公民身份号码", "value": "9999...", "confidence": 0.98,
     "bbox": [..],                                 // 加分项：原图画框
     "validation": {"passed": true} }],
  "issues": [{"field": "有效期", "reason": "起始日期晚于截止日期"}] }
```

**块标签映射**（两条路径产出同一种标签）：

| 统一标签 | 扫描页来源（PP-StructureV3） | 电子页来源（PyMuPDF） |
|---|---|---|
| text | layout text 区域 | get_text("blocks") 段落 |
| title | layout title | 字号/编号模式（第X章、一、） |
| table | layout table（HTML） | find_tables() 包装成同款 HTML |
| figure | layout figure | get_image_info() 大图 |
| figure_caption | layout figure_caption | 图上下方短文本行（图注绑定） |
| page_header / page_footer | layout header/footer | 页面上下 7% 带内短行（下游可过滤页码噪声） |

## 4. 关键难点和做法

**难点 1：表格按行列还原（不揉散）**
电子页用 `find_tables()` 直抽矢量结构（零识别误差）；扫描页 PP-StructureV3 输出 HTML（支持合并单元格）；管线内表格全程 HTML，禁止任何"清洗"拍平；同时生成**每行带表头的影子文本**供检索/导出。备选：无线框表格识别差时，裁区域用正则+坐标聚类兜底拼列。

**难点 2：烂图识别（倾斜/翻拍/模糊/红章压字）**
- 倾斜/弯曲：引擎三开关；任意角度残留靠检测模型 ±15° 容忍度，评测失分再补 OpenCV minAreaRect 纠偏。
- **红章压字**（印章管理规定.pdf 就是活样本）：HSV 红色掩码抑制预处理，识别质量差的页自动启用重试。
- **低分辨率扫描**（质量手册实测仅 ~100 DPI）：不重采样放大文件，取内嵌图 1.5~2 倍放大保证行高可检；质量哨兵标"源件精度不足"。

**难点 3：字段校验（规则全量覆盖）**

| 证件 | 校验规则 |
|---|---|
| 身份证正面 | GB11643 校验位；出生日期 == 证号 7~14 位；性别 == 第 17 位奇偶；证号断行容错（归一化去空白后匹配） |
| 身份证反面 | 日期合法性；有效期起 ≤ 止 |
| 营业执照 | 统一社会信用代码 GB 32100 mod-31 校验位；成立日期合法；营业期限起止顺序 |
| 驾驶证 | 证号按身份证规则校验；有效期起止；准驾车型枚举 |

校验不过 → 字段标"有问题" + 置信度压 0 + 写明原因（如"校验位错误，期望 X 实际 Y"）。低置信（<0.7）单独标"建议人工复核"。

**难点 4：证件类型可配置（现场演示彩蛋）**
每类证件一个 YAML：分类关键词 + 字段（类型→校验器）+ 锚点正则 + 交叉校验表达式。新增证件 = 新增一个文件，启动时扫描注册，零代码改动：

```yaml
type_id: id_front
classification_keywords: ["居民身份证", "公民身份号码", "出生"]
fields:
  - name: 公民身份号码
    type: chinese_id          # 内置校验器：校验位+出生+性别
    anchor: ["公民身份号码", "身份号码"]
    pattern: '\\d{17}[0-9Xx]'
  - name: 有效期限
    type: date_range          # 校验起止顺序
cross_checks:
  - expr: "出生日期 == idcard_birth(公民身份号码)"
    error: "出生日期与身份证号不一致"
```

**难点 5：长任务接口（吸取 leaudit 教训：不能同步阻塞）**
证件同步返回（秒级）；文档立即返回 task_id + 轮询接口，状态机 queued→running→done/failed（细 phase：解析中/第 N 页/完成），**必有终态**；批量任务单文件失败不影响其他，`/retry_failed` 只重跑失败项；失败带错误分类（格式错误/页数超限/OCR 质量可疑/内部错误）。

## 5. 数据设计

核心表（SQLite）：

- `documents(id, sha256, filename, kind[card|doc], created_at, result_json)` —— sha256 唯一索引，防重复识别
- `tasks(id, document_id, batch_id, status, phase, progress, error_code, error_msg, duration_ms, created_at, updated_at)`
- `batchs(id, total, done, failed, created_at)` + `batch_items(batch_id, task_id, file_sha256, status, retry_count)`
- `eval_runs(id, ground_truth_file, created_at, report_json)` —— 评测结果留存

证件 YAML 配置目录：`config/certs/*.yaml`（启动扫描注册）。

## 7. 怎么证明做好了

**证件评测**：导入标准答案（含自造测试集）→ 一键报表：按证件类型、按字段的准确率；**错误检出率**（识别错的字段中被标"有问题"的比例——考核明确看这条）。

**文档准确率（自设计）**：对 3 份给定 PDF 人工校对出 golden 文本，然后统计：
- 字级准确率：归一化（去空白/全半角统一）后编辑距离比对；
- 表格还原率：单元格文本匹配率 + 行列结构正确（单元格相对位置）；
- 页面方式判定正确率：text_layer/ocr 标注与人工判断一致的比例；
- 耗时：每张、每页实测。

**自造测试集（评分项）**：PIL 合成虚构证件生成器，每类 ≥10 张，扰动矩阵：扫描（噪点）/翻拍（透视+光照不均）/倾斜（±15°）/模糊（高斯）/反光（高光斑)/**号码故意错误**（喂校验器）；**生成时同步产出标准答案 JSON**（格式同官方）。人名/号码/单位全部虚构。

**预期指标**：证件字段准确率 ≥95%（清晰件 ~99%，翻拍/反光件 ≥90%）；错误检出率 ≥90%；文档字级准确率 ≥97%（电子页 ~100%）。
