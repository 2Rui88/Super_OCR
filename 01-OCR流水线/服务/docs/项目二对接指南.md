# 项目二（制度知识库）对接指南

OCR 服务 HTTP API v1，Base URL `http://<ocr-host>:8700/api/v1`。
接口字段级文档见 [API接口文档.md](API接口文档.md)，本文只讲对接姿势。

## 你会用到哪几个接口

| 场景 | 调用序列 |
|---|---|
| 证件图片入库 | `POST /cards`（默认同步等待） |
| 扫描/电子 PDF 入库 | `POST /documents` → `GET /tasks/{id}` 轮询 |
| Office 文档入库 | 同上——直接 `POST /documents` 传 doc/docx/xls/xlsx/ppt/pptx，服务端自动转 PDF |
| 批量入库 | `POST /batches` → `GET /batches/{id}` → （可选）`POST /batches/{id}/retry_failed` → `GET /batches/{id}/export` |

## 证件：同步调用，把 202 当正常状态

```python
import httpx

with httpx.Client(base_url="http://127.0.0.1:8700/api/v1", timeout=90) as api:
    response = api.post("/cards",
                        files={"file": open("cert.jpg", "rb")},
                        data={"type": "id_front"})   # type 可省略=自动判断
    if response.status_code == 200:
        body = response.json()
        if body["kind"] == "card":
            fields = {f["name"]: f["value"] for f in body["result"]["fields"]}
            review = [f["name"] for f in body["result"]["fields"] if f["needs_review"]]
        else:  # kind == "document"：不是证件，已按文档识别
            text = "\n".join(b["text"] for p in body["result"]["pages"] for b in p["blocks"])
    elif response.status_code == 202:          # 60 秒没识别完，任务还在跑
        task_id = response.json()["task_id"]   # 转异步轮询，见下节
```

**三条规则**：
1. 202 不是错误——任务在继续跑，拿 `task_id` 轮询即可；
2. `kind=document` 表示图片不是支持的 4 类证件（响应里有原因说明），结果换成文档结构，不要按证件字段解析；
3. `needs_review=true` 的字段要人工复核（校验不过或置信度低），`issues` 里有原因。

## 文档：异步 + 轮询节奏

```python
task_id = api.post("/documents", files={"file": open("scan.pdf", "rb")}).json()["task_id"]

import time
delay = 2.0
while True:
    task = api.get(f"/tasks/{task_id}").json()
    if task["status"] in ("done", "failed"):
        break
    time.sleep(delay)
    delay = min(delay * 1.5, 10.0)   # 2s 起步 ×1.5 退避，封顶 10s

if task["status"] == "done":
    result = task["result"]["result"]
    for page in result["pages"]:
        mode = page["source_mode"]   # text_layer=直读 / ocr=扫描识别，逐页标注
```

文档结果每页带 `source_mode`（统一 StructureV3 后恒为 `ocr`，仅为兼容保留）、
块级 `bbox`（归一化 0~1）、表格 `html`。整篇 Markdown 直接用 `result["markdown"]`
不行时按块自取。

**统一链路说明**：所有文档（含 Office 转换件）逐页走 PP-StructureV3，产出同构的
标题/表格/阅读顺序结构。同内容重复提交（原件哈希一致）命中文档级缓存秒回，
知识库侧不必再为省时做"电子版跳过 OCR"之类的特殊处理。

## 失败处理与重试规则

| error_code | 含义 | 建议 |
|---|---|---|
| WORKER_LOST / SERVICE_RESTARTED | worker 崩溃/重启，任务中断 | 直接重新提交（同内容会命中缓存，秒级） |
| WORKER_ERROR | 处理异常 | 重试一次；仍失败则保留 error_message 送人工 |
| UNSUPPORTED_FORMAT / FILE_TOO_LARGE | 上传即被拒 | 不可重试，检查文件 |
| CONVERT_FAILED / DOC_TOO_LONG | Office 转 PDF 失败（损坏/加密/超时/超 200 页） | 不可重试，检查源文件 |
| attempts≥3 | 重试到顶（永久失败） | 走人工 |

**去重**：文件按内容 SHA-256 寻址。证件识别与文档识别（含 Office 转换件）
重复提交均命中结果缓存毫秒级返回；知识库侧按哈希去重提交仍是最佳实践
（省一次上传与排队）。

## 版本与兼容

- 路径前缀 `/api/v1`；响应 JSON 结构变更走版本号（v2），v1 内只增字段不改旧字段；
- OpenAPI 文档：`GET /openapi.json`（Swagger UI 在 `/docs`），字段以它为准；
- 上传限制：图片 jpg/jpeg/png/bmp/webp ≤20MB；文档 pdf/doc/docx/xls/xlsx/ppt/pptx 同限；服务端按文件头验真。
