# 项目二《制度知识库》实施方案（v4 · 定稿）

基于 v3 + 四处定稿修订：①出处恢复章节标注（面包屑）；②队列闭环心跳租约（删启动清扫、加丢租约止损）；③关键词检索双字词回退、拒答闸门双路皆弱；④重新解析从存档 JSON 重放不重烧 OCR。
P1 契约以 `01-OCR流水线/服务/docs/API接口文档.md` 为准（已实现并冻结）。

## 〇、设计基线（三句话）

1. **识别全部外包给项目一**：所有文件转 PDF 后经项目一异步接口识别，返回 JSON 整包存档——解析详情、索引重放、错误归因的唯一事实源；
2. **块是一等公民**：档案 = 文件名 + 页码 + bbox + 类型 + 章节面包屑，检索文本 = 文件名 + 块内容；出处统一"文件名 · 章节 · 第 N 页"+ 点击定位；
3. **LLM 只在三个受控点位**：多轮改写、答案生成、评测判分；拒答闸门前置在生成之前，双路皆弱才拒。

## 一、总体架构

```
前端5屏(照原型) ─HTTP/SSE─→ p2-kb(FastAPI+SQLite+FAISS+DashScope)
                              │ HTTP(异步提交+轮询, 契约冻结)
                              ▼
                        p1-ocr(API:8700 + 双worker + tasks.sqlite3 心跳队列, Paddle)
存储卷：kb.db(真身) │ uploads/(原件) │ crops/(裁图) │ faiss索引(可再生缓存)
```

三条边界：P1 只管"PDF→结构化块"，契约 JSON 冻结不改；全系统文字识别 100% 出自项目一，Qwen-VL 只描述箭头关系；SQLite 是真身、FAISS 是缓存——重建索引零 API 费用。时间统一 unixepoch 整数。

## 二、数据模型（SQLite WAL，七张表）

```
documents  id, filename, fmt, sha256, status, worker, heartbeat_at(int), attempts, error,
           page/table/figure_count, superseded_by, p1_result_json, created_at
chunks     id, doc_id, page_num, bbox, type(text/table_row/table_full/figure),
           heading_path(章节面包屑), seek_text, html, crop_path, linear_text, vl_desc,
           source_mode, ocr_confidence, embedding(BLOB), faiss_id
conversations / messages / eval_items / eval_runs
```

## 三、任务队列（心跳租约 · 定稿）

```
领单  UPDATE documents SET status='处理中', worker=:主机名:pid, heartbeat_at=now,
      attempts=attempts+1 WHERE id=:id AND status='待处理'   ← rowcount=1 即 commit
      候选 ORDER BY id LIMIT 3，落空换下一个
心跳  先睡后跳每30s：UPDATE … SET heartbeat_at=now
      WHERE id=:id AND status='处理中' AND worker=:me      ← 仅持有者生效
      命中→renewed；0行再查：就绪/失败→finished；待处理/他人持有→lost
      → 置事件 → 取消执行协程止损；DB异常连续3次(~90s)才判lost
回收  30s定时器(挂消费循环)：status='处理中' AND heartbeat_at < now-300
      → attempts<3 回'待处理'重投 / ≥3 落failed终态；条件UPDATE幂等，任何实例执行都安全
终态  仅持有者可写(WHERE带worker匹配)；丢租约者影响0行
清扫  无。崩溃自愈=周期回收兜底(最迟~330s重投)；多实例不抢活任务，水平扩容天然成立
排空  停机等在途协程≤5s，等不完交给回收兜底
水位  GET /api/queue/stats → pending/处理中/failed + 最老任务年龄
```

闭环收益：管理员对"处理中"文档点重新解析（重置行）→ 旧协程下轮心跳发现 lost 自动止损，管理端零取消逻辑。
实现纪律：LibreOffice 转换、裁图走线程池；调 P1 用异步 HTTP；事件循环不被阻塞（自测：长文档处理中问答屏仍流式输出）。

## 四、五条链路

**A 导入（异步）**：上传秒回 → 队列逐份领单推进

```
A1 收件：批量接收、sha256去重、入队幂等(同文件在途→"已在处理")、原件存uploads/
A2 转格式：.doc/.docx → LibreOffice → PDF；.pdf直通（此后只有一条解析路径）
A3 识别存档：POST /api/v1/documents(202, task_id) → 轮询 GET /api/v1/tasks/{id}
    (2s起×1.5退避封顶10s, done/failed终态) → result.result JSON整包落库；
    WORKER_LOST/SERVICE_RESTARTED → 指数退避重新提交
A4 过滤打档案：丢页眉页脚；跟踪最近TITLE/图注 → heading_path面包屑；
    档案=文件名+页码+bbox+类型；seek_text=文件名+块内容
A5 分装：TEXT/TITLE → 相邻合并≤500字 → text块（TITLE文字拼开头）
    TABLE → 每行一块 + 整表一块（行影子文本检索、HTML展示）
    FIGURE → 一图一块（图注拼进文本）；CAPTION并入不单独成块
A6 图加工：bbox本地裁图(144dpi) → VL结构描述 → 与linear_text拼接；
    VL节点名⊆OCR文字交叉校验，不过即降级+warning
A7 上架：seek_text≥2字才向量化 → embedding写SQLite BLOB → FAISS增量add；
    并发闸门≤8+429退避；选"替代旧版本"→旧文档superseded_by新文档
```

**B 问答（SSE）**：①有上文先 LLM 改写 → ②双路检索（FAISS 向量 Top20 ∥ FTS5 trigram Top20，查询不足三字或 trigram 无命中回退 LIKE；滤旧版）→ ③RRF 融合 Top8 → ④拒答闸门：向量 Top1 余弦 <0.55 **且**关键词路无命中才拒 → ⑤编号块 + 三条铁律（只依据资料/必须标[n]/不足必说）→ ⑥流式生成 + citations + 旧版提示

**C 出处（点击）**：`GET /api/chunks/{id}` 分流渲染——正文→bbox 高亮；表格→HTML+命中行高亮；流程图→crop 图；出处文案"文件名 · 章节 · 第 N 页"；附下载原件/跳文档库。一个 chunk_id 锁死一切。

**D 索引同步**：删除→清块+remove_ids 增量摘；重新解析→从 p1_result_json 重放 A4 起（不重烧 OCR，秒级），行重置由租约闭环自动止损旧协程；重建按钮→BLOB 重放 FAISS（零 API 费，兼压实）。

**E 评测**：35 题 CSV（正文15/表格8/流程图4/查无5/新旧版2/多轮1）→ 逐题走真实链路 B → LLM 判对错 + 查无判拒答 + 出处比对金标 → 五项指标（总正确率/出处/表格/查无/耗时）+ 逐题归因（source_mode+confidence → OCR 错/检索错/回答错）

## 五、关键实现与取舍

| 模块 | 实现要点 |
|---|---|
| DashScope 客户端 | embedding/VL 走原生端点、chat 走兼容端点；关思考+reasoning 兜底；Semaphore(8)+429 指数退避 |
| FAISS 管理 | IndexIDMap2+FlatIP；向量真身存 SQLite BLOB；Python 字节流落盘（规避 Windows 中文路径）；add/remove_ids 增量摘 |
| 摄入队列（租约闭环） | 表即队列、条件 UPDATE 抢占、心跳续租三态、丢租约 cancel 止损、finish 持有者校验、周期回收幂等、入队幂等、水位 |
| 检索 | RRF 融合、FTS5 trigram + 双字词 LIKE 回退（df 过滤停用词） |
| 并发闸门 | asyncio.Semaphore（单实例够用） |
| 摄入编排 | 转 PDF / 分装 / 章节面包屑 / 裁图 / VL 编排 / 问答编排均为本项目按需求实现 |
