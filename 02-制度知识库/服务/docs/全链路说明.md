# 项目二（制度知识库）全链路说明

> 本文描述从"上传一份制度文件"到"问答给出带出处的回答"的完整链路，
> 每一步对应代码位置，失败时系统如何自愈。所有代码路径均相对 `02-制度知识库/服务/`。

## 0. 部署拓扑

```
┌─────────────────────── 本地（开发/演示机） ───────────────────────┐
│  项目二 API + 摄入 worker        浏览器页面                       │
│  127.0.0.1:8800                 http://127.0.0.1:8800            │
│      │                                                            │
│      │ httpx（127.0.0.1:8700）                                    │
│      ▼                                                            │
│  SSH 隧道入口 8700 ═════════════════════╗                         │
└─────────────────────────────────────────╬═════════════════════════┛
                                          ║ ssh -N -L 8700:127.0.0.1:8700
                                          ▼
                            ┌── GPU 服务器 ──────────────────┐
                            │ 项目一 OCR（API:8700 + worker）│
                            │ PaddleOCR / PP-StructureV3     │
                            └────────────────────────────────┘
```

- 项目二自己**不做任何 OCR**，所有识别都通过 `POST /documents` + `GET /tasks/{id}` 调项目一；
- 隧道断线是自愈的（见 §5 失败矩阵）；
- 模型能力（向量化/问答/VL）走 DashScope API，密钥在 `服务/.env`，不进仓库。

## 1. 全链路总览

```
 A1 收件          A2 转格式        A3 识别(调项目一)      A4/A5 分块入库
┌──────────┐   ┌──────────┐   ┌──────────────────┐   ┌──────────────────┐
│ 上传API   │   │ doc/docx │   │ 提交PDF→轮询任务  │   │ 过滤页眉页脚      │
│ 校验/去重 │──▶│ →PDF     │──▶│ (退避轮询+进度    │──▶│ 章节面包屑        │
│ 落盘入队  │   │ pdf直通  │   │  透传+租约自检)   │   │ 正文合并/表格双粒度│
└──────────┘   └──────────┘   └──────────────────┘   │ 图注归并          │
                                                      └────────┬─────────┘
 A6 图加工                     A7 向量化上架                    │
┌──────────────────┐   ┌──────────────────┐                  │
│ 按bbox裁图       │   │ seek_text→向量   │                  │
│ +VL结构描述      │──▶│ BLOB存真身       │◀─────────────────┘
│ +交叉校验防幻觉  │   │ FAISS上架+FTS同步│
└──────────────────┘   └────────┬─────────┘
                                │ status=ready
                                ▼
 B 问答（消费链路）
┌────────────────────────────────────────────────────────────┐
│ 多轮改写 → 双路召回(向量+关键词) → RRF融合 → 拒答闸门        │
│   → 编号块+三条铁律 → 流式生成 → 引用出处 → 会话存档         │
└────────────────────────────────────────────────────────────┘
```

摄入链（A1→A7）把一份文件变成"可检索的知识"；问答链（B）消费这些知识。
全程由**心跳租约队列**护航（§2.2），任一环节崩溃都会被自动回收重投。

## 2. 摄入链：从上传到就绪

### 2.1 A1 收件 —— `app/api/routes_documents.py` `POST /api/v1/documents`

| 步骤 | 说明 |
|---|---|
| 校验 | 扩展名白名单 `.doc/.docx/.pdf`；单文件 ≤20MB（与项目一上限一致） |
| 指纹 | sha256 内容寻址——同内容永不重复存储 |
| 落盘 | `uploads/{sha前16}{ext}`（`pipeline.store_upload`，同文件零拷贝） |
| 幂等入队 | `queue.enqueue`：同内容在途→`inflight`（复用）；已就绪→`duplicate`；曾失败→重置重投 |
| 版本替代 | 表单 `replaces=旧文档id`：首个文件消费，替代关系先声明后落实（§2.8） |

接口**秒回** `results[]`（逐文件 ok/原因），处理全部异步。

### 2.2 队列与租约 —— `app/queue.py` + `app/worker.py`

`documents` 表的行本身就是队列（无独立 MQ）：

- **领单**：`claim_next` 条件 UPDATE 抢占（候选 LIMIT 3，被抢走换下一个），
  并发上限 `KB_INGEST_CONCURRENCY`（默认 2，信号量控槽）；
- **心跳租约**：处理中每 30s `renew_lease`（仅持有者可续）；`set_phase`
  推进阶段时顺带续租。三态：renewed / finished / lost；
- **回收**：`processing` 且 5 分钟无心跳 → 次数未超限回 `pending` 重投，
  超限落 `failed`。条件 UPDATE 幂等，任何实例执行都安全；
- **止损**：轮询项目一期间持续 `holds_lease` 自检——行被人工重置/接管时
  立即放弃，不给项目一留下无人认领的孤儿任务。

### 2.3 A2 转格式 —— `app/pipeline.py` `convert_to_pdf`

统一收敛到 PDF，此后只有一条解析路径：

- `.pdf` 直通；`.doc/.docx` 走 LibreOffice headless（PATH 探测 + 标准安装
  路径探测），本机无 soffice 时退 Word COM；
- 产物按内容寻址 `data/converted/{sha16}.pdf`——重复导入零转换；
- 单次转换 180s 超时；跑在线程池（`asyncio.to_thread`），事件循环不被
  阻塞，**长文档处理中问答 SSE 仍流式**。

### 2.4 A3 识别 —— `app/p1client.py` `recognize_pdf`（跨服务边界）

```
POST {KB_P1_BASE_URL}/documents  (multipart)      ──▶ 202 {task_id}
GET  {KB_P1_BASE_URL}/tasks/{task_id}             ──◀ 轮询
```

| 机制 | 参数/行为 |
|---|---|
| 轮询退避 | 2s 起步 ×1.5，封顶 10s（`KB_P1_POLL_START/MAX`） |
| 总超时 | 3600s（`KB_P1_POLL_TIMEOUT`，覆盖 P1 的 200 页上限在 CPU 下的识别时长） |
| 进度透传 | P1 的 `phase`（"识别中 第n/N页"）实时写入 `documents.phase`，前端可见 |
| 租约自检 | 每次轮询前 `alive()` 检查，租约丢失立即放弃 |
| 可重试错误 | `WORKER_LOST` / `SERVICE_RESTARTED` → 自动重新提交（≤2 次，`KB_P1_RESUBMIT_MAX`） |
| 上传超限 | HTTP 413 → `FILE_TOO_LARGE` 直接失败（不可重试） |
| 结果 | `task.result.result` = 项目一 `DocumentResult`：`pages[].blocks[]`，块含 type/bbox(归一化)/text/html/row_texts/linear_text/confidence，页含 source_mode |

### 2.5 A4+A5 打档案与分块 —— `app/pipeline.py` `pack_chunks`

把项目一的统一块结构变成"检索与出处的一等公民"（`chunks` 行）：

| 块类型 | 处置 |
|---|---|
| page_header / page_footer | **丢弃**（页眉页脚是噪声） |
| title | 刷新章节面包屑 `heading_path`；正文块前缀`【章节】` |
| 正文 text | 同页相邻合并（≤`KB_TEXT_MERGE_MAX` 500 字/块），bbox 取并集；无 TITLE 时用"第X章/附录X/X、"正则兜底识别标题 |
| table | **双粒度**：`table_full`（整表，HTML 全程保留）+ 每行 `table_row`（带表头前缀的影子文本 + row_index，命中可高亮行） |
| figure | `caption + linear_text` 组装（流程图节点文字按坐标序） |
| figure_caption | 并入同页最近的 figure；图注先于图出现时充当面包屑 |

每块写 `seek_text = 文件名\n内容`（检索文本）、`source_mode`、`ocr_confidence`。
重放安全：先 DELETE 旧行再批量 INSERT。

> 附：`rescue_figures`（流程图补救）为兼容保留——项目一统一 StructureV3 后
> 所有页 `source_mode` 恒为 `ocr`，不再出现 `text_layer` 候选页，此步骤空转。

### 2.6 A6 图加工 —— `app/figures.py` `process_doc_figures`

- 按 bbox 以 **144dpi（与项目一识别同基准）** 从 PDF 裁图 → `data/crops/`；
- 有 DashScope 密钥时调 VL 模型生成流程图结构描述；
- **交叉校验防幻觉**：VL 提到的节点名必须 ≥一半能在 OCR 的 `linear_text`
  里找到，否则弃用描述、降级为纯 OCR 文字；
- 通过校验的 `vl_desc` 追加进 `seek_text`（可被"流程图经过哪些节点"这类
  问题检索到）。

### 2.7 A7 向量化上架 —— `app/pipeline.py` `embed_doc_chunks` + `app/vector.py`

- 无 `DASHSCOPE_API_KEY` 时**安全降级**：跳过向量化，FTS 关键词检索仍可用；
- `seek_text` 超过"文件名+2字"门槛的块批量 embedding，向量以 BLOB 存
  `chunks.embedding`（**BLOB 是真身，索引只是缓存**）；
- FAISS `IndexIDMap2 + IndexFlatIP`，id 复用 chunk id，增量 `add_chunks`
  上架并持久化 `data/faiss.index`；
- 关键词路：`chunks_fts`（FTS5 trigram）由**触发器**随块写入自动同步。

### 2.8 终态落账 —— `queue.finish`

就绪时一次性写：`status=ready`、页/表/图统计、`p1_result_json`
（项目一返回整包存档 = 事实源，重新解析不重烧 OCR）、`pdf_path`；
若声明过 `replaces_target` → 旧文档标 `superseded_by=新id`（检索默认过滤
旧版，问答末尾提示"存在旧版本"）。

## 3. 问答链（消费） —— `app/api/routes_qa.py` `POST /api/v1/qa/ask`

SSE 事件流：`citations → delta* → refuse|done`。

| 步骤 | 说明 | 代码 |
|---|---|---|
| ① 多轮改写 | 有对话历史才调 LLM，把"那副高级呢？"补全成独立问题；失败用原问 | `retrieval.rewrite_query` |
| ② 双路召回 | 向量路 FAISS Top20（余弦）；关键词路 FTS5 trigram Top20，双字词/无命中回退 LIKE bigram；两路统一 df 过滤（高频词当停用词） | `retrieval.search` |
| ③ RRF 融合 | K=60，双路名次倒数融合，取 Top8 | 同上 |
| ④ 拒答闸门 | 向量 Top1 < 0.80 **且** 关键词路无命中才拒（"双路皆弱才拒"，关键词精确命中不误杀） | 同上 |
| ⑤ 编号块+铁律 | 8 个块编号 [1..8]；system 提示词三条铁律：只依据资料/必须标编号/不足必须说"没有找到相关规定"。**问答与评测共用同一份提示词**（口径不漂移） | `retrieval.build_messages` |
| ⑥ 流式生成 | chat 流式 delta；引用列表 `citations` 先行下发 | `llm.chat_stream` |
| ⑦ 旧版提示 | 命中文档曾替代旧版时，末尾追加"存在旧版本，按最新版回答" | `retrieval.old_version_hint` |
| ⑧ 会话存档 | 问答与引用写入 conversations/messages，多轮上下文取最近 6 条 | `routes_qa._persist` |

**出处链（链路 C）**：引用点击 → `GET /chunks/{id}` 一个 id 锁死一切——
文件名/页码/bbox（前端画框）/表格 HTML/流程图裁图（`GET /crops/{id}`）/
原件下载（`GET /documents/{id}/file`）。出处文案如
`联调测试制度.pdf · 第二章报销标准 · 第1页（表格第3行）`。

## 4. 辅助操作

| 操作 | 接口 | 行为 |
|---|---|---|
| 重新解析 | `POST /documents/{id}/reparse` | 重置行重投。就绪文档从存档 `p1_result_json` **重放 A4–A7，不重烧 OCR**；处理中文档可重置，旧执行者由租约闭环止损 |
| 删除 | `DELETE /documents/{id}` | 先摘 FAISS 索引再删行/块（FTS 随触发器同步）；被它替代的旧版恢复可见 |
| 重建索引 | `POST /index/rebuild` | 从 SQLite BLOB 全量重放 FAISS（零 API 费，兼压实） |
| 队列水位 | `GET /queue/stats` | 各状态计数 + 最老 pending 年龄 + 活跃 worker 数（堵"进程活着但没人消费"盲区） |
| 评测 | `POST /eval/items/import` + `/eval/run` | CSV 导入六类题型（正文/表格/流程图/查无/新旧版/多轮）→ 跑同构问答链路 → LLM 判分 → 运行历史。见 `app/evalservice.py` |

## 5. 失败与自愈矩阵

| 故障 | 现象 | 系统行为 |
|---|---|---|
| SSH 隧道中断 | httpx 连接错误 | 本次 attempt 失败 → 自动重排队（≤3 次）；隧道恢复后重提交，**项目一内容缓存命中，秒级返回不重烧 GPU** |
| 项目一 worker 崩溃/重启 | 任务 `WORKER_LOST`/`SERVICE_RESTARTED` | `p1client` 自动重新提交（≤2 次） |
| 项目一处理异常 | `WORKER_ERROR` | 随摄入 attempt 重投；3 次后 `failed`，`documents.error` 留因 |
| 上传即被拒 | `FILE_TOO_LARGE`/`UNSUPPORTED_FORMAT` | 不可重试，直接失败 |
| 项目二进程崩溃 | 行停在 processing | 5 分钟无心跳被回收 → 重投或落 failed |
| 手动重置/接管 | 租约易主 | 原执行者 `alive()` 自检放弃执行，不写脏数据 |
| 转换失败 | soffice/COM 异常 | attempt 失败重投；3 次后 failed |
| VL/向量化失败 | 单块降级 | 块保留，关键词检索仍可用；索引可重建 |
| FAISS 索引损坏/换模型 | 维度不符 | 检测到 meta 不匹配自动重建；`/index/rebuild` 手动兜底 |

## 6. 数据模型（两张核心表）

- **documents**（`app/db.py`）：行 = 文件 + 队列任务。关键字段：
  `sha256`（内容寻址）、`status`（pending/processing/ready/failed）、
  `worker`+`heartbeat_at`（租约）、`phase`（阶段文案）、`pdf_path`、
  `p1_result_json`（项目一整包存档）、`superseded_by`/`replaces_target`
  （版本替代）、页/表/图计数。
- **chunks**（`app/db.py`）：行 = 检索与出处的一等公民。关键字段：
  `type`（text/table_row/table_full/figure）、`heading_path`（章节面包屑）、
  `seek_text`（检索文本）、`html`（表格真身）、`bbox`（归一化坐标，前端画框）、
  `row_index`（表格行高亮）、`crop_path`/`linear_text`/`vl_desc`（流程图三件套）、
  `embedding` BLOB + `faiss_id`（向量真身与索引位）。

## 8. 验证过的链路表现（2026-11-20 联调实测）

- 2 页中文 PDF（标题层级 + 带线框表格）：上传 → 就绪约 40 秒（GPU 服务器上更快）；
- 分块正确：目录三级标题全识别、章节面包屑准确、表格产出整表 + 3 行影子文本；
- 问答"市内出租车报销限额"：2.2s 回答"200 元（实报）"，首条引用精确到
  **表格第 3 行**（`row_index` 高亮可用）；
- P1 逐页进度（"识别中 第1/2页"）实时透传至项目二文档列表。
